# 07 - 启动与验证

## 7.1 启动

```bash
# 确保 Redis 在跑（没有的话）：
docker run -d -p 6379:6379 --name hono-redis redis:7

cd /c/Users/malei/Desktop/hono
pnpm dev
```

看到 `server listening on http://localhost:3000` 即成功。再跑一遍类型检查：

```bash
pnpm typecheck
```

## 7.2 逐场景验证

### ① 健康检查（公开）

```bash
curl -s http://localhost:3000/health
# {"ok":true}
```

### ② 未登录访问受保护接口 → 401 + Bearer 质询

```bash
curl -si http://localhost:3000/auth/me
```

预期：

```
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="api"
x-request-id: <uuid>

{"code":"AUTH.SESSION_TOKEN_MISSING","message":"缺少有效的登录 Token"}
```

### ③ 注册 → 拿 token

```bash
curl -s -X POST http://localhost:3000/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"account":"demo001","password":"password123"}'
# {"token":"<TOKEN>"}
```

把 token 存起来：

```bash
TOKEN=<上一步返回的 token>
```

### ④ 参数校验失败 → 400 + details

```bash
curl -s -X POST http://localhost:3000/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"account":"ab","password":"123"}'
```

预期：

```json
{
  "code": "COMMON.VALIDATION_FAILED",
  "message": "请求参数校验失败",
  "details": [
    { "path": "account", "code": "too_small", "message": "..." },
    { "path": "password", "code": "too_small", "message": "..." }
  ]
}
```

### ⑤ 携带 token 访问 → 200

```bash
curl -s http://localhost:3000/auth/me -H "Authorization: Bearer $TOKEN"
# {"user":{"userId":"...","sessionId":"..."}}
```

### ⑥ 权限不足 → 403

```bash
curl -s -X POST http://localhost:3000/companies \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"acme"}'
# {"code":"ACCESS.FORBIDDEN","message":"没有权限执行此操作"}
```

给演示用户授权后再试（临时验证用，在 `access.service.ts` 的构造函数里加一行，或直接在代码里调用）：

```ts
// access.service.ts 构造函数末尾，仅调试用：
this.grant('<你的 userId>', 'platform.company.create')
```

重启后重试 ⑥ → 201。

### ⑦ 登出 → token 立即失效（不透明 token 的服务端吊销）

```bash
curl -s -X POST http://localhost:3000/auth/logout -H "Authorization: Bearer $TOKEN" -o /dev/null -w '%{http_code}\n'
# 204

curl -s http://localhost:3000/auth/me -H "Authorization: Bearer $TOKEN"
# {"code":"AUTH.SESSION_INVALID","message":"登录已失效，请重新登录"}
```

### ⑧ 404 也走统一结构

```bash
curl -s http://localhost:3000/no-such-route
# {"code":"COMMON.NOT_FOUND","message":"请求的资源不存在"}
```

## 7.3 验收清单

- [ ] 所有错误响应都是 `{code, message, details?}` 结构
- [ ] 401 响应带 `WWW-Authenticate: Bearer realm="api"`
- [ ] 每个响应都带 `x-request-id`
- [ ] 控制台只在 5xx 时输出 `http_request_failed` 日志，且日志里没有 token/密码明文
- [ ] 未挂 `accessPolicy` 的业务路由在 review 中被拦截
